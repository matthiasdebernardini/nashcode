nashcode
features github

your own forge,
on your own tailnet

Every repository is a durable object with its own SQLite database, replicated to a bucket you own. Stacked-diff review, plans, and a kanban board your agents can drive. No accounts — your tailnet is the perimeter.

get the source quickstart
~ zsh
$ nashcode setup
✓ dgit deployed on celld · bucket wired · tailnet serving
$ nashcode init my-notes
✓ repository created · origin wired · pushed
$ nashcode invite ada
✓ token minted · send her the snippet

durable by construction

dgit on celld: each repo is one cell, one SQLite file, replicated to S3-compatible storage. Kill the box; the repos come back bit-identical.

stacked review

Branch stacks inferred from the graph, rendered with Pierre diffs. Merge and restack from the browser — force-pushes are leased and atomic.

plans & board

Markdown in plans/ and tasks/ is the database. Agents push plans, you annotate, cards flip to done on merge.

agents welcome

Every surface is JSON. Comments, CI, board moves, and a /brain endpoint that hands an agent the state of everything.

ci that is just a script

.nashcode/ci at your repo root. Green dot or red dot, logs in the viewer. Deploys are the script's business.

code intelligence

Every repo indexed: definitions, references, callers, the whole call graph as JSON. nashcode grep is rg-shaped, but hits come back annotated with kind and caller counts.

your error tracker

A Sentry-compatible DSN, so your deployed apps report crashes here. Stack frames link straight into the code browser at the failing line.

the whole stack

A repo declares its upstream column — server, runtime, OS — and the viewer mirrors and indexes it, so you trace a symptom across codebases like one system.

an architecture that answers

A living diagram of the system where every node links back to the code, folded into /brain so agents start oriented.

not a github replacement

The private layer for work in flight. Public repos, releases, and outside collaborators stay where they are.
